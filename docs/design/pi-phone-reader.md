# Pi phone reader: source-backed UI slice

## Scope

Improve the native Android reader attached to an existing Pi session: message-type hierarchy, code and JSON readability, bounded tool details, and machine-name headers. Issue [#33](https://github.com/azusachino/cappuccino/issues/33) tracks the live work. This is not complete Pi parity, typed approvals, or a new backend.

## Sources and reuse boundary

- [RikkaHub tool UI](https://github.com/rikkahub/rikkahub/blob/c907608bc198e5ad90333320170be40a3b49634a/app/src/main/java/me/rerere/rikkahub/ui/components/message/ChatMessageTools.kt): native Compose tool summaries open a separate result-reading surface. Its repository is AGPL-3.0; no implementation code, artwork, or branding is copied. Adapt only the interaction pattern using ordinary Material 3 components.
- [MikePenz 0.45.0 highlighted-code component](https://github.com/mikepenz/multiplatform-markdown-renderer/blob/v0.45.0/multiplatform-markdown-renderer-code/src/commonMain/kotlin/com/mikepenz/markdown/compose/elements/MarkdownHighlightedCode.kt): reuse the already-installed renderer/code module for syntax highlighting, language headers, horizontal code scrolling, and copying. The renderer is [Apache-2.0](https://github.com/mikepenz/multiplatform-markdown-renderer/blob/v0.45.0/LICENSE). No dependency upgrade, fork, custom tokenizer, or WebView.
- [Pi session format](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/src/core/session-manager.ts): structured message roles and tool-call/result identity remain the data authority. A terminal fallback must not masquerade as canonical history.

Repository popularity is selection evidence, not a correctness gate. RikkaHub had approximately 8,100 stars and recent maintenance when inspected; smaller search matches were not treated as mature merely because their README listed features.

## Reader contract

- User bubbles, named agent prose, thinking disclosures, and tool disclosures have explicit text labels and distinct Material surfaces; color is not the sole discriminator.
- Tool arguments and results are separate sections. Valid JSON is pretty-printed with the existing JSON library and highlighted as JSON. Other output remains literal text; formatting never changes protocol data.
- Inline tool previews contain at most twelve lines and 4,000 Unicode code points. Truncated content has an explicit full-detail action opening a native scrollable dialog. No original result is discarded.
- Opening a disclosure enters manual reading mode. Live updates must not automatically drag the reader to the tail; the existing follow-latest control restores following explicitly.
- Code highlighting follows the app's actual light/dark Material theme, not only the device theme. The upstream language/copy header is used. Installed Highlights 1.1.0 has no JSON language enum: pretty-printed JSON explicitly uses its existing JavaScript literal lexer while retaining the truthful JSON header. A regression checks that this produces bounded highlight spans; physical color rendering still needs device verification.
- Machines is a machine-grouped agent tree: agents from every connected machine are always visible beneath their own node, with no expansion tap or intermediate Agents screen. MacMini and Linux mini require independent verified connections; opening one conversation is a viewer choice, not permission to disconnect the other server. This owner correction supersedes the earlier single-active-connection implementation. The redundant select-machine/saved-count banner is removed; bottom navigation is Machines, Attention, Settings. Children are shown only after each profile's verified connection and filtered by that machine's UUID; stale or foreign agents cannot appear under another machine. Each profile owns discovery state, a cancellable request job and stale-response generation. Foreground-only five-second roster refreshes do not restart the selected stream; manually disconnected profiles stay disconnected until their own Connect/Refresh action. Node Refresh/Disconnect/Remove affects only that profile; the toolbar has no global refresh/close action and disconnected nodes have no duplicate Connect/Retry text button. The inline refresh icon reconnects its own machine. Add verification/failure does not cancel or replace an existing conversation or another machine's work. Selecting an agent opens its conversation directly. Back returns to the always-visible active branch and preserved list position without stopping the remote agent. Frequently used Refresh and Disconnect are inline icon buttons on each machine row, with machine-specific accessibility labels. Rename, connection details and removal remain in a consistent text-only node overflow menu. Composer/disclosure saveable state, reading-position state and follow preference are keyed by profile plus machine UUID plus agent locator, not just a locator that can repeat on another server. Old asynchronous stream/action failures cannot overwrite the newly selected machine. Chats is not a competing top-level destination; the old saved tab value is migrated for compatibility.
- The bridge adds optional `machine_name` metadata to `/api/session`, from the operating system's configured hostname. Machine UUID and protocol version remain unchanged. Pairing uses that name by default, and verification migrates only old URL-derived defaults; owner-provided names are never overwritten. Older bridges lacking the field remain connectable. Tapping the conversation machine name permits a local override.
- URL, machine UUID, pane ID and session locator are available in Connection details, not normal headers or list summaries. Machine and agent rows use standard Material 3 ListItem components.
- Closed tool rows show the actual command or path, wrapping over three lines with a native overflow indicator. Expanded argument sections show wrapped command text without requiring horizontal scrolling; structured JSON remains available separately.
- Preserve passive links/images, ALT handling, device-local timestamps, Activity-owned bars, multiline composer, refresh, and disconnected/unavailable states.

## Settings, palette and agent icons

The owner's follow-up selects F-Droid 2.0's restrained grouped preferences and GitHub/VS Code-inspired light/dark colors. This supersedes the earlier stock Material palette restriction; native Material controls, typography and accessibility remain in use. The [GitHub VS Code theme](https://github.com/primer/github-vscode-theme/blob/main/src/theme.js) supplies the neutral canvas/foreground/blue-accent direction; this is an adaptation, not an exact TextMate theme port. No wallpaper-derived colors are enabled by default. Fenced code uses GitHub Light/Dark colors mapped onto Highlights 1.1.0's native token categories, following the resolved app theme. This covers conversation Markdown, tool sections and full readers without replacing the lexer. The conversation app-bar title is a single centered icon/title row aligned with Back; machine naming remains in its tree-node menu and identity in Connection details.

Settings is a scrollable preference list with Appearance (theme selection), Machines (navigation to the existing parent screen), and About & diagnostics (real connection status/details and generated app version). No placeholder features or decorative cards. Small original vector icons distinguish Pi, Agy, Claude and Codex; unknown agents have a neutral fallback. These are functional glyphs, not official trademarks and not a claim of additional capabilities.

An expanded tool shows its command/path once, separately from the remaining structured arguments; the full reader follows the same rule. Protocol input remains unchanged.

## Connection diagnostics

Connection details replaces raw machine/pane/session IDs with app version, bridge package version, protocol requirements and boolean bridge capability advertisement from the verified handshake. Protocol conflicts fail closed with an explicit required/received version error. Missing legacy metadata is **Not reported**, never **Unsupported**. Explicit false flags disable prompt controls and are rejected by the client before transmission. Metadata is bound to the verified machine; inactive/disconnected entries are last-verified information rather than current compatibility or health claims. Connection and selected-agent runtime errors remain separate from advertised endpoint support. Canonical history versus scrollback fallback is reported when known. No diagnostic inspection sends prompts or approvals.

## Compact information and visible tool results

Owner-approved UX-1 direction starts with a compact native machine sheet: identity/state, App/Bridge versions, Technical details and local Rename. Technical details replaces the sheet with a separate Activity-hosted view using the reader's centered app-bar title and native back-arrow icon; Back returns to information. Main-screen saveable state retains composer drafts/disclosures, identity/list state remains scoped, and inspection pauses following. Versions from inactive/disconnected profiles remain labeled last verified; metadata from another UUID never appears. Normal connections do not show the capability dump or a compatibility paragraph.

The owner additionally requires tool results, especially failures, to be visible on mobile. Results have a default literal preview even when the tool disclosure is collapsed. Pi's actual `isError` value is preserved by exact tool-call association into optional `is_error`; missing legacy flags remain unknown, not success. Explicit failures open by default with a Failed label and Error section. Bounded failure previews include the beginning and ending of long output so a final diagnostic is not silently lost; full literal output remains available. Unknown/normal text is never classified as failure by keyword matching.

A visible Follow live output switch defaults on and is remembered per profile/machine/agent conversation. Off prevents new output or manually reaching the bottom from enabling automatic following. On follows new content; scrolling away or inspecting pauses reading with a Paused while reading label. Jump to latest moves once and does not override an explicitly disabled switch. This is viewport following, not a new remote subscription or prompt action.

Owner-selected chat surfaces keep replies inline: agent content uses the neutral surface-container-low background, user content retains its primary-container bubble, with native Markdown/tool disclosures and full-content access unchanged. The redundant Conversation · Pi subtitle is removed. Context reports machine, the basename of the bridge-reported working directory, and its reported branch; full working directory is available in Technical details. Directory is display metadata only, never a session-resolution heuristic. A root-workstation main branch is not relabeled as an inferred vendor branch. Unknown history and explicit scrollback fallback are distinguished.

The owner rejected the first full-width agent rectangles as still transcript-like. Revised treatment uses left/right message bubbles with a directional corner and an opposite-side gutter, putting the device-local timestamp inside prose rather than repeating speaker/time headers. Tool and thinking activity stays outside those prose bubbles in original part order, with operation/status icons, literal previews, disclosure and full-reader access. The full reader has a Close icon in its header. Technical details uses grouped native label/value rows for Machine, Versions, Bridge support and Current agent, not a colon-delimited text dump.

Pi responses retain actual record boundaries and timestamps instead of merging successive assistant records into one dated turn. Each tool optionally reports its source-record started_at and ID-matched result-record finished_at; the UI calls the latter Result received, not inferred execution duration. Unknown times remain absent. Explicit assistant stopReason aborted/error becomes a chronological response_status part (including empty aborted responses), retaining partial content; it does not mark every pending tool cancelled or imply disconnection. These additive parts/fields retain protocol 1. Matching, unsupported sources and legacy no-ID behavior remain guarded.

The owner approved standard JSON gzip middleware as a specific exception to the no-new-dependency constraint. A local phone-facing sample was 377,231 bytes uncompressed and 72,426 bytes with command-line gzip; one 28 ms local transfer is not evidence of a phone bottleneck or measured gzip latency improvement. tower-http negotiates gzip for ordinary JSON only, excluding SSE/WS. OkHttp's existing transparent decoding is retained, including the decompressed 2 MiB limit. Compression is not authentication; the existing loopback/tailnet trust boundary is unchanged.

Owner-approved tool-activity separation places a quiet translucent Show tool activity pill in flow above the composer, with actual total/failed/awaiting-result counts. It does not overlap text, keyboard or system bars. Prose stays in chat bubbles; tool-only records keep compact timestamped markers linking to their operations. Failed-tool notices and bounded literal error previews remain in the main conversation; response abort/failure notices remain visible. The chronological native tool sheet opens at the chosen marker or latest operation, retaining actual timestamps, arguments/results, disclosure and full-reader popup. Opening pauses following; dismissal does not disconnect, send prompts or navigate away from the selected agent. Sheet state resets with machine/agent identity.

The common ToolActivityState mapping supplies awaiting-result, result-available and failed states to both disclosure and aggregate counts. Explicit failure without output is failed, not simultaneously pending; missing flags/results are not successful or cancelled. Pi/Agy wire interpretation remains in bridge adapters and the UI sheet consumes normalized ConversationPart tool entries, with no provider-specific dispatch. This strengthens the existing seam without a parallel provider framework.

The owner corrected the first tool pill implementation: an in-flow control and repeated per-turn operation-count links still cluttered chat. The revised reader removes ordinary tool-only records/count markers from the chat list (all operations remain in the chronological sheet). Actual failed-tool previews/details links and response abort/failure notices remain visible. Tools and Jump to latest share one translucent floating action surface, aligned at the reader's bottom end above the composer. Tail clearance derives from the surface's actual measured height so latest content can scroll clear; neither action has a separate layout layer or steals a composer row. Tool counts/status details remain available through accessibility labels and the sheet.

Owner-approved responsive conversation refinement groups each visible source message into one directional block, including all prose paragraphs, thinking/outcome details and its timestamp. Incoming/outgoing blocks derive their width from actual viewport constraints, keep a side gutter, cap readable width on larger windows, wrap text and grow vertically without fixed message heights. Failed-tool notices use contained error blocks; hidden tool-only records produce no stray timestamp footer.

Android retains at most 200 source messages and 100 tool operations across those messages, in original order, in addition to existing byte limits. Prose, outcomes and full output of retained tools are not truncated by the count window. Earlier-history omission is explicit in chat and tool activity; no claim of full archive access is made. Original tool-part ordinals remain stable as the window rolls. Following compares provider-neutral visible message content only: hidden tool invocation/result/time/status changes do not request a chat scroll or raise Jump to latest. New tool activity instead causes two finite colour pulses on the shared floating surface, with no size/layout animation and no historical-load pulse. Inspection still pauses following and hard Off is respected.

The owner's subsequent correction moves tool errors entirely into the tool sheet: they must not leak as chat message previews. The floating Tools control shows a blue recent total and explicitly labeled red failed count, plus finite new-activity pulses. Real response failure/abort blocks remain in chat, distinct from tool failures. This supersedes the earlier inline failed-tool preview treatment; failure visibility is now the count/indicator and inspectable sheet, not repeated error bodies in the conversation.

Physical dark-mode capture exposed a real design defect: surfaceContainerLow equaled the screen canvas, hiding incoming message boundaries. Replies now use the distinct surfaceContainerHigh token; their visible clock is compact HH:mm inside the block, with the full device-local timestamp retained for accessibility. Long prose and literal fallback output use bounded six-line/600-code-point previews with full selectable reading access; unverified Agy scrollback is not presented as canonical structured history or amplified into large Markdown headings. The old fallback heading heuristics are removed. Tool failure count is numeric red (no visible failed suffix); its meaning remains in the accessibility label. The alarming whole-surface colour pulses are replaced by one small stationary blue update dot with a 600 ms opacity transition, no background flashing, scaling or layout movement.

A physical Agy capture still showed oversized H2 text because verified structured prose continued to use the renderer's default displayMedium heading style. Message previews now explicitly use the pinned renderer's public typography override: H1–H6 are bodyLarge semibold. Lists, emphasis, code, tables and the passive-content boundary are retained; full reading keeps document typography. This is shared chat presentation, not an Agy-specific string-rewrite or provider branch.

The owner found provider response-failure rows unhelpful in chat. Inspection confirmed recorded details terminated and exceeded request buffer limit while retrying upstream, rather than a phone-side action. Failed response metadata remains recorded and accessible as Last response issue in Technical details, but is excluded from chat and its follow-content signature; any partial prose remains. Explicit aborted outcome remains distinct. Connection, identity/protocol and prompt-delivery errors are not suppressed by this presentation change.
